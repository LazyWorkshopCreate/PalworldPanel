RELEASE NOTES

v0.1.0-rc.1

2026-10-06

This is the first PalworldPanel release candidate for managing multiple Palworld instances on a single server. The panel runs as a Windows service or Linux container, while game instances run in Docker Linux containers. The console supports world creation, settings changes, backups, recovery and daily maintenance.

Highlights

  • Create independent worlds or take over existing instances through a controlled workflow, with separate directories, saves, passwords, ports, backups and task locks.
  • View the game IP address, UDP port, game version and resource allocation in the instance list; check runtime status, players, FPS and resource usage in instance details.
  • Allowlisted visitors can view a read-only dashboard without signing in. Set the panel administrator password on first access, then sign in for management actions.
  • Search game settings by Chinese name or field and compare current, default and draft values. Edit settings in dialogs, with unapplied drafts highlighted.
  • Enter or randomly generate game administrator and access passwords, then save them as drafts. Only their configured status is shown; existing passwords are never displayed.
  • Background tasks report initialization and maintenance stages and outcomes. Instance actions require confirmation, configuration application prevents duplicate submissions, and logs show the latest entries first.
  • Schedule daily backups, create manual offline backups, restore through controlled workflows, export encrypted recovery points and import world ZIP files.
  • The Windows installer supports reconfiguration or program-only upgrades, checks Docker, listening addresses and ports, and swaps the complete program directory to avoid obsolete files.
  • Provide a bilingual product website, feature documentation, user guide and release notes, with redacted console screenshots in the feature documentation.
  • Include Linux/Windows testing and pipelines that build release packages and deploy GitHub Pages from version tags.

Lifecycle acceptance fixes

  • Check disk headroom before allocating a new instance or task.
  • Disable instance mutations while a task is queued, running, or awaiting recovery.
  • Keep instance locks outside directories being quarantined or permanently removed on Windows.
  • Compare additional settings by content so applied settings no longer incorrectly block upgrades.
  • Show backups in chronological order, newest first, rather than by random identifiers.
  • Validate and write empty technology lists correctly when registering and adopting a supported container.
  • Recheck registered container IDs after adoption rollback so a removed container does not prevent later adoption.

Upgrades and compatibility

  • For an existing Windows installation, choose Upgrade program only to retain configuration, administrator accounts and instance data. Choose Reconfigure when deployment settings need to change. Back up management data and game saves before upgrading.
  • Windows defaults to HTTP and supports local loopback access. For Linux deployments, configure TLS, persistent directories and Docker socket permissions as documented.
  • Connect using the instance's displayed IP and UDP port; the game port is not a website endpoint. Management interfaces are restricted to explicitly allowlisted private-network addresses and should not be publicly exposed.
  • World ZIP imports preserve the target instance's passwords, ports and rules. Automatic player identity migration from single-player, co-op hosts or other platforms is not guaranteed.

Verification and limitations

  • Existing backend, frontend and local Docker Desktop verification records cover instance isolation, configuration application, task locking, backups and recovery, and Windows deployment workflows. Consult the repository's verification documents for detailed results.
  • This is a release candidate. Installation on the target host, real game-client connectivity and player recovery require acceptance checks for the actual deployment. A healthy management API does not establish game connectivity.
  • The Windows installer is not code-signed. The panel has local Docker administration privileges; configure an exact IP allowlist and firewall as documented.
  • Public UDP forwarding and diagnostics are outside the panel's scope. The management console currently uses Chinese.

Release assets

  • Linux x64 Docker panel image archive
  • Windows x64 self-contained program ZIP
  • Windows x64 Inno installer
  • SHA256SUMS checksum manifest

Read the user guide before deployment and verify downloads against SHA256SUMS. Prefer the Windows installer for installation and upgrades that swap the program directory; use the program ZIP for manual deployment.
