Release notes/v0.1.0-rc.3

RELEASE NOTES

v0.1.0-rc.3

2026-10-11

Adds player connection controls and save-file lists on the World tab, improves task fault isolation, scheduled backup retries and administrator authentication, and fixes instance switching, locking and sampling failures.

Features and improvements

  • The World tab lists known players, online status, banned user IDs and matching save files. Running instances use loopback game APIs for kick, ban and unban; stopped instances only update their own ban list.
  • World-tab state is isolated by instance and refreshed five seconds after each read completes. Failed reads show stale-data notices and recover on later samples. Save-list failures do not hide an available player roster.
  • Invalid task payloads and execution failures become failed or pending-attention tasks with redacted diagnostics instead of terminating the executor.
  • Scheduled backups retry only failures in the preflight phase on the same day, for up to three attempts. Successful backups and attempts that reached other phases are not repeated.
  • Backup-policy changes require recent administrator authentication. Expired sessions retain form input for submission after login. Action and sampling errors are displayed separately.

Fixes

  • Connection controls hold the same OS instance lock as other writes and check instance and active-task state inside the lock, preventing concurrent ban-list updates and overlap with restore or startup operations.
  • Instance switches clear old players, confirmation dialogs and passwords, cancel old requests and ignore late responses, preventing old-player commands from targeting a different instance.
  • Game API connection failures and timeouts fall back to remembered players and banned IDs. Request cancellation continues to propagate.
  • Player rosters enumerate save filenames without decompressing save bodies, so corrupt save containers cannot block the roster projection.
  • Reduce repeated active-task queries and Docker address lookups when a recent sample is available.

Upgrading and compatibility

  • Back up panel management state, the master key, deployment configuration and game saves before upgrading. Resolve active tasks and retain the previous program or image with its matching state for rollback.
  • On Windows, choose Upgrade program only to retain accounts, configuration and instance data. On Linux, update the panel image while preserving persistent mounts. Updating the game is not required.
  • A player-history table is created when the management database opens, storing players observed by the panel per instance. Rollbacks should use matching previous management state; full compatibility with older programs is not guaranteed.
  • This version does not provide save-value editing or player-save isolation. The console remains in Chinese, and management interfaces retain LAN allowlist, session and CSRF protections.

Validation and limitations

  • Passed 187 backend Release tests and 107 frontend tests on Windows, plus Prettier, TypeScript/Vite builds, documentation and whitespace checks.
  • Regression coverage includes instance-lock conflicts, active restore tasks, instance switching, late responses, independent reads, automatic refresh recovery, game API failures and request cancellation.
  • Cloud Linux/Windows CI, Docker builds, installer packaging and asset validation are performed by the release workflows; this note does not claim results before those runs finish.
  • Real-game kick, ban and unban operations, player login and character recovery remain untested for the new World tab. Automated checks do not replace production or player acceptance.
  • Windows installers are unsigned. Public UDP forwarding, monitoring and diagnostics are outside the panel's scope.

Release assets

  • Linux x64 Docker panel image archive
  • Windows x64 self-contained program ZIP
  • Windows x64 Inno installer
  • SHA256SUMS checksum manifest

Verify SHA-256 checksums before installing or upgrading, then follow the user guide.
