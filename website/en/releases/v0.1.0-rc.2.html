RELEASE NOTES

v0.1.0-rc.2

2026-10-07

Adds console URL routing and game update checks, with clearer action feedback and mutual exclusion. Memory admission now uses available capacity, and fixes cover Linux adoption, maintenance restarts and false configuration drift. Existing rc.1 management data can be retained when upgrading.

Features and improvements

  • URL routing for the dashboard, instances, host and security, and every instance tab, with direct links, refresh, and browser history support.
  • Shared action descriptions, state checks and mutual exclusion. Conflicting operations remain disabled while tasks are queued, running or awaiting resolution.
  • Improved feedback for actions in the More menu, with a narrower, left-aligned menu. Instance actions continue to require confirmation.
  • Updates start with a version check. The console clearly reports when no update is needed, or displays current and target versions when available. Technical image and installation fields are hidden. Upgrades validate the target installation and running version and retain paired recovery points.
  • Memory summaries distinguish usage, allocation and total capacity. Creation and explicit starts check current available memory, system reserves and other pending starts, without counting stopped instance allocations again.

Fixes

  • Generate secure UUID command keys when crypto.randomUUID is unavailable over LAN HTTP, allowing browser actions to submit normally.
  • Check an existing parent volume when a new Linux instance directory does not yet exist, and safely handle host-network containers without port mappings.
  • Support adopted templates with existing wildcard UDP bindings and no query port, preserving host game ports and forwarding behavior while keeping management interfaces on loopback.
  • Resume maintenance of an already running instance without reserving its entire unchanged memory allocation again. Creation and explicit starts still require fresh admission checks.
  • Prevent INI number and boolean formatting changes on shutdown from triggering false source drift. Real changes to parameters, passwords, unknown fields and other sections remain detectable. Legacy fingerprints migrate only for unchanged configurations without active tasks.
  • Improve backend diagnostics by logging exception types and call locations without request contents or potentially sensitive exception messages.

Upgrading and compatibility

  • Back up panel state/private directories, the master key, deployment configuration and game saves, and resolve active or pending tasks before upgrading. Retain the previous image or installer for rollback.
  • On Windows, select Upgrade program only to preserve accounts, configuration and instance data, or Reconfigure when deployment settings need to change.
  • On Linux, load the new image, update the panel image version and recreate the panel container while preserving persistent paths and mounts. Updating the panel does not require updating existing games.
  • Before rolling back to rc.1 after the new fingerprints are enabled, restore the matching previous management state. Do not run the previous program against the upgraded database alone.
  • This is a release candidate. The management console remains in Chinese, with the same exact LAN IP allowlist and loopback management interface restrictions.

Validation and limitations

  • Passed 163 backend tests on each of Windows and Linux, 99 frontend tests, TypeScript/Vite builds, formatting and documentation checks.
  • Tested creation, parameter and password draft application, backups, restore and rollback, ZIP imports, encrypted exports, rule cloning, quarantine and undo, container removal with retained data, unmanagement and re-adoption through APIs and the web interface on Linux.
  • Adopted two existing Linux servers for write management, verifying preserved worlds, game credentials, gameplay settings, ports and resource limits. Scheduled backups are managed by the panel.
  • Verified maintenance memory admission during concurrent starts, browser application locking and release after completion, and action submission over LAN HTTP.
  • Real game-client login, original player-character recovery, cross-version game upgrades, permanent deletion after the retention period and recovery after a full host reboot remain unverified. API health does not prove gameplay connectivity.
  • Windows installers are unsigned. Public UDP forwarding and diagnostics are outside the panel's scope.

Release assets

  • Linux x64 Docker panel image archive
  • Windows x64 self-contained program ZIP
  • Windows x64 Inno installer
  • SHA256SUMS checksum manifest

Verify SHA-256 checksums before installing or upgrading, then follow the user guide.
