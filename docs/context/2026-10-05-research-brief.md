# 调研与设计任务书

后续范围更新（2026-10-05）：技术栈按本项目规范确定；后端拥有 root/Docker 管理权限且只允许白名单内网 IP 访问；公网 UDP 在面板范围之外，面板不承担公网转发、监控、诊断或外网验收。以下问题保留为初始任务书，当前范围以 [决策状态](../README.md#决策状态)及需求、设计、计划为准。

其余设计已按用户最佳实践决策授权确定，见[运维策略与工程默认值](../design/2026-10-05-operational-defaults.md)；原任务书中的“尚未决定/待确认”属于历史描述，不构成重复确认要求。工程验证与生产实施授权仍独立。

用户目标：简单控制面板，管理同一台服务器上的多个幻兽帕鲁实例。请在本仓库完成调研与设计，暂不实现生产业务代码，不修改已有服务器。

## 需要回答的问题

1. 比较官方 REST API、RCON、Docker/Compose 的能力边界，哪些操作需要调用容器或修改文件。
2. 比较现成帕鲁面板、通用游戏面板、自建轻量面板的适用性；从官方或维护者来源核实能力、维护状态、许可和成本。
3. 比较 .NET/C#、Node/TypeScript、Python 的简单单体方案，推荐一个容易由个人维护的技术栈；技术栈尚未决定。
4. 管理入口放在 example-host 本机、独立容器还是通过 SSH？如何兼顾 Docker 权限、管理员登录、凭据存储和任务执行？
5. 如何接管既有两实例、不重新创建世界，避免标签和目录约定与手工 Compose 不兼容？
6. 如何创建、启停、重启、升级、克隆配置但不克隆存档、删除实例（明确区分保留或删除存档）？
7. 配置如何读写、校验和显示“待重启/已生效”？至少覆盖名称、密码、玩家上限、死亡掉落、离线惩罚、建筑衰减、资源限制和备份。
8. 如何提供实时健康、资源用量、玩家数、FPS、天数、据点数量、脱敏日志、连接地址和 UDP 网络诊断？
9. 如何导入 Saved.zip、保存世界、校验压缩包与路径、备份、恢复、回退、处理世界 GUID 与玩家身份迁移？不得把 API 可用等同于玩家角色已恢复。
10. 如何分配不冲突的游戏 UDP、查询 UDP 和管理端口，防止把 REST/RCON 暴露公网？把隧道能力不足、UDP 不可达、密码错误和版本不一致区分清楚。
11. 如何设计单实例任务互斥、幂等、进度反馈、超时、失败重试和可恢复状态，避免一个操作影响另一实例？

## MVP 建议候选

单服务器、单管理员；列表和详情、接管既有实例、创建新世界、启停、常用设置、健康和日志、手动/定时备份、ZIP 导入与回退。公网隧道自动配置、计费、集群、多租户是否延后，应说明理由。
