# 运行可维护性设计

版本日期：2026-10-10。修订日期：2026-10-10。状态：已实现。适用范围：REQ-21。替代来源：无。验收见[验证记录](../verification/2026-10-10-runtime-maintainability.md)。本文件补充 [系统设计](2026-10-06-system-design-r4.md) 的任务失败处理和 [运维策略](2026-10-05-operational-defaults.md) 的每日备份规则；不改变锁顺序、恢复事务和单执行器模型。

## 诊断日志

执行器注入日志组件，最低级别仍为 Warning。每条失败记录使用结构化字段：任务编号、类型、阶段、终态、结果码、异常类型、脱敏详情。详情经过现有日志脱敏，最长 4000 字符；不打开秘密库去比对明文密码。Docker 适配器在命令退出码非零时记录命令名、退出码和同样脱敏截断的标准错误，不记录完整参数。`PanelException` 的接口消息保持原来的泛化文案。

## 执行器隔离

领取循环只负责调度。单条任务的载荷解析放进该任务自己的异常处理。任务状态仍为 Queued 时失败，终态写 Failed，活动任务唯一索引不再占用该实例。状态已是 Running 且阶段为 Preflight 或 Save 时写 Failed；其余 Running 阶段写 NeedsAttention，并沿用停服保护。循环外侧再捕获遗漏异常：能读到的任务按同一规则落库，然后继续处理其他排队任务。两条路径都写诊断日志。

## 定时备份补试

调度键保持 `schedule-{实例编号}-{北京时间日期}`。补试键为同一前缀加 `-retry-2`、`-retry-3`。纯函数根据当日调度任务决定下一键：

| 当日已有任务 | 下一动作 |
|---|---|
| 无 | 使用当日主键，第 1 次 |
| 全部为 Failed 且阶段为 Preflight，次数小于 3 | 使用下一个补试键 |
| 成功、取消、回退、排队、执行中、待处理，或失败阶段不是预检 | 不入队 |
| 已有 3 次 | 不入队 |

补试只新增一条备份任务，不复制恢复点，也不删除旧任务。实例锁和幂等键规则不变。错过窗口后的首次入队仍合并为一次；成功后的当天不再补跑第二份快照。

## 备份策略认证

`PATCH /api/v1/instances/{id}/backup-policy` 在修订号检查之前调用近期认证。会话超过 5 分钟返回现有 `ReauthenticationRequired`。前端备份策略表单独立保存输入；收到该结果时展示管理员密码，登录成功后刷新 CSRF 并提交同一次策略。其他字段校验、只读实例拒绝和未结束任务冲突保持不变。

## 控制台提示与采样

操作失败和采样失败使用两个独立提示。操作提示使用 alert，采样提示使用 status。采样请求成功时只清除采样提示。备份策略表单、提示组件与调度文案从页面壳分开，页面壳继续持有路由和实例选择。

活动任务查询为一条 `state IN ('Queued','Running','NeedsAttention')`。内存预约仍只统计 Queued 与 Running。观测采样成功后 5 秒内，实例列表的地址直接读取该次采样中的游戏地址；采样失效、过期或尚不存在时仍按原路径检查容器。

## 失败处理

日志写入失败不得代替任务落库。任务落库失败时执行器记录异常类型并继续循环，避免一条坏数据终止进程。补试查询失败时本轮跳过该实例，下一分钟再读。近期认证失败不修改实例修订号。
