# 内存采样与准入设计

日期：2026-10-07。状态：已实现。对应 REQ-20。

游戏运行环境从 Linux 内核 /proc/meminfo 读取 MemTotal 与 MemAvailable；使用中 = MemTotal - MemAvailable，包含可回收缓存的可用值，不能使用 MemFree 或累计限额推算。

优先通过正在运行的容器读取同一内核数据；所有容器停止时用本地已批准游戏镜像启动一个只读、无网络、32 MiB 上限的临时采样容器，固定 /bin/cat 命令，无数据挂载、不下载镜像，退出自动移除。命令中断尝试移除该命名探针；无法读取拒绝准入，不假定内存充足。

Windows 检查 min(物理主机可用内存, Linux 游戏环境可用内存)。可启动预算 = 实时可用内存 - 系统预留 - 其他 Queued/Running 创建或启动任务的完整配额，最低为零；不扣除停止实例配额。当前任务按实例身份排除自身预约，其他任务按实例去重。未结束任务的配额保守保留至任务完成，避免启动过程的短时低占用导致重复准入。

创建提交、新启动入队和实际 Compose 启动共用 allocation.lock；预检不保证后续提交成功，提交与执行阶段重新采样。原实例锁和任务幂等继续有效。CPU 是共享配额，单个新实例仍不得超过逻辑核数减系统预留，不累加停止实例的 CPU 配额。

列表的已分配仅供观察，不能作为不足告警依据；使用中和总量采用游戏环境口径，主机监控仍保留物理 Windows 系统采样。

维护事务在停服前记录实际运行状态及已应用内存限额。原本运行且目标限额未增加时，备份、重启、接管、规则应用及世界交换后的恢复使用原运行分配；仍持有实例锁、分配锁并验证世界、规则和限额。原本停止的实例、显式启动、新建以及增加限额的应用继续完整准入检查，防止将短暂停服误判成新增申请而留下已完成备份但无法恢复的服务。
