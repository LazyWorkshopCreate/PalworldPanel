# 运维策略与工程默认值

日期：2026-10-05。状态：按用户“其他部分按最佳实践原则决策”的授权采纳；2026-10-06 已在本机实现，生产未部署。D1/D2/D6 保持用户已确定的边界。本文规定其余默认值，设计中的可配置初值以本文为准；初值不代表性能测试结果。

## 选择原则

单服务器、单管理员、单个面板容器与持久化执行器，不引入集群、微服务或远程执行。复用已验证镜像，不因存在新镜像迁移现有实例。先只读登记，再独立执行写接管；目录、世界和 Compose 身份保持原位。未经后续明确要求，不部署或修改生产实例。

## 已确定的操作策略

| 编号 | 决策 | 理由与边界 |
|---|---|---|
| D2 补充 | 独立 Linux Docker 容器、UID 0、Docker socket、host 网络；直连 Kestrel LAN HTTPS 18080 | 同一个发布物、可访问游戏回环 API；仅批准目录挂载、不用 privileged。socket 仍是宿主 root 等价权限；IP 白名单、登录与 CSRF 必须全部成立 |
| D3 | 每日离线一致备份，北京时间 05:00/05:15 错峰，保留 14 天 | 运行实例先 save、停服并确认停止，复制完整 Saved 与配置、校验后恢复原运行意图；原本停止的实例保持停止。失败不删除旧点；停服时间需演练测量，不承诺固定时长 |
| D4 | 关闭启动更新和外部自动升级，升级由显式任务执行；正常运行 restart=unless-stopped | 普通重启不改变游戏版本。文件变更及验证启动期间 restart=no；验证通过才解除 hold。升级前保存旧安装副本、镜像 digest、配置和存档，回退必须整组匹配 |
| D5 | MVP 仅支持 Linux 专用服务器同平台 ZIP 导入；未知兼容性先隔离演练 | 不自动转换合作主机、单机或跨平台身份，不改二进制存档；保留目标规则、密码、端口，原玩家真实 LAN 入服后才接受导入 |
| D7 | 新建与启动检查实时可用内存、重 IO 串行、默认保留数据、清理先隔离 | 对已有超额只告警；不自动削减资源、不删除未知归属目录。所有操作使用实例锁、持久任务及可恢复文件 journal |

写接管切换时统一备份/更新/重启调度所有者，停用冲突的镜像脚本和外部任务。只读接管期间保留现状；无法排除外部写入者则不开放写管理。错过备份合并为一次，不补跑多份；锁冲突的待执行备份也合并。受保护点包括最后一个已验证备份、未接受导入/升级的回退点和任务引用文件，保留期不能覆盖保护标记。

备份使用 SHA-256、manifest 与归档可读性检查，恢复可用性由恢复演练证明。每日备份设计目标为正常调度下最多约 24 小时进度损失；失败后实际恢复点年龄可能更长，应告警。恢复耗时尚未测量，不承诺 RTO。升级/导入前另建恢复点。

提供手动加密导出与异机恢复手册；管理员应保留至少一份独立介质副本，并演练解密恢复。自动云备份不进入 MVP。下载不得明文输出配置秘密；独立密钥通过受控离线介质/密码管理器保管。单盘备份不能抵御宿主磁盘损坏，页面显示最近导出记录，导出记录不等于独立副本已验证。

面板 SQLite 使用 Online Backup API 生成数据库快照，不直接复制正在使用的主数据库文件；在无文件事务的 checkpoint 暂停执行器变更，配套保存 journal、schema/keyVersion 与受限密钥备份说明。恢复时先检查一致性再启用执行器，数据库快照不等于游戏存档备份。[SQLite 官方备份 API](https://www.sqlite.org/backup.html)。

## 容量与生命周期

宿主预留 4 GiB 内存给系统、面板及维护。2026-10-07 用户调整后，新建与启动按实时可用内存检查，停止实例配额仅展示、不计入准入预算；不因外部容器未设限额拒绝创建，其实际占用由内核采样涵盖。等待启动任务保留预约，Windows 同时检查物理宿主和 Linux 游戏环境。完整契约见[内存准入设计](2026-10-07-memory-admission.md)。

新实例初始模板 4 CPU、16 GiB，玩家上限 16；模板不是小世界或高并发稳定性承诺。单个新实例 CPU 配额不超过逻辑核数减 2，CPU 为共享配额。预留和最低内存仍通过受控宿主配置设置，不以累计分配替代实时采样。

磁盘预检按操作逐项计入旧数据恢复点、目标 staging、压缩输出、旧安装副本和可能下载空间；不以压缩大小估算展开需求。完成后还须保留所在文件系统总量 10% 与 10 GiB 中的较大值；任一相关文件系统不满足则拒绝。实时核实容量，不沿用快照。重 IO 并发 1；不同实例轻操作和只读监控可继续。

删除默认仅移除指定容器并保留数据；取消接管不停止实例。永久清理要求近期认证、预览确认、停服、验证独立最终备份，再同根隔离 7 天；到期由明确清理任务删除，仍需归属及保护引用检查。最终备份至少保留 30 天，期限到达且为唯一可信备份时继续保留。已有实例永久清理默认禁用，须先核定目录归属；禁止全局 prune/down -v。隔离期间可恢复，正式删除后仅能从备份恢复。

## 可配置工程初值

以下是保护性起点，由 W01/W03/W09/W10 演练校准；变更需校验并留审计，不允许无限超时、无限解压或无保留上限。

| 项目 | 初值与失败行为 |
|---|---|
| REST / 停服 / 安装升级 / 恢复归档 | 10 秒 / 120 秒 / 30 分钟 / 60 分钟；超时核实进程及状态，破坏性步骤不自动重跑；需要放宽时在执行前设置 |
| 锁 / 查询重试 | 等待 5 秒后返回任务冲突；幂等读取最多 3 次退避；不自动重复文件交换、删除或更新 |
| 状态采样 / 设置采样 / 陈旧标记 | 5 秒 / 60 秒 / 连续 30 秒未成功；限并发及响应量 |
| 登录 / 会话 / 危险操作认证 | 每账号连续 5 次失败暂锁 15 分钟，辅以来源限流；闲置 30 分钟过期；危险操作要求 5 分钟内重新认证 |
| 确认令牌 | 10 分钟有效，单次使用，绑定用户、实例、动作、preview hash 与配置修订；过期重新预检 |
| ZIP | 上传 4 GiB、展开 20 GiB、100,000 文件、单文件 8 GiB、压缩比 200:1；目录与流式计数双重限制；包结构安全规则不可关闭 |
| 临时上传 | 未被活动任务引用且 24 小时未使用则清理；失败事务证据须先完成处置，不能被临时清理删除 |
| 日志 | 默认尾部 200 行，单次最多 2,000 行且 1 MiB；运行日志与审计初始保留 30 天，活动恢复任务证据继续保留；脱敏、限速、磁盘预算 |

镜像使用验证后的 digest，NuGet/pnpm 使用依赖锁；不定时自动更新到 latest。保留兼容性矩阵、数据库迁移前快照及回退手册。公网 UDP、外部网络设施状态和隧道操作均不进入这些策略。

## 实施输入与证据

实际 LAN 监听 IP、逐个允许的客户端 IP、TLS 证书与信任链、宿主实例/备份目录、生产维护窗口公告方式是部署输入，由实施时填写并只读核实；不使用示例地址自动放行。已选择的策略无需再次征求方向确认。样档兼容、停止行为、归档耗时、故障恢复、资源峰值和真实玩家验证仍是工程门槛，全部未运行。后续生产操作仍需用户明确要求。

恢复顺序与停止后手动操作以维护者文档为参考；正常策略与临时 hold 的区别按 Docker 官方语义实现并演练。[恢复指南](https://palworld-server-docker.loef.dev/guides/backup/restoring-backup)、[版本固定与降级风险](https://palworld-server-docker.loef.dev/guides/pinning-game-version)、[Docker 重启策略](https://docs.docker.com/engine/containers/start-containers-automatically/)。
