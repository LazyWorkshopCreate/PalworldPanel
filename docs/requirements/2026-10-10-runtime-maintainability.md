# 运行可维护性需求

版本日期：2026-10-10。修订日期：2026-10-10。状态：已实现，验收见[验证记录](../verification/2026-10-10-runtime-maintainability.md)。适用范围：单管理员面板的任务执行、定时备份、备份策略和已登录控制台。替代来源：无。对应 REQ-21，不替代 REQ-08、REQ-12 的恢复点、实例隔离和危险操作确认。

## REQ-21 故障留在本任务内，并且能够事后诊断

- REQ-21.1 任务执行失败、启动时发现中断任务、以及 Docker 命令非零退出，都在面板日志留下任务编号、类型、阶段、结果码和异常类型。日志先按现有规则脱敏并截断。任务接口、页面文案和问题响应不返回堆栈、命令输出、密码或内部路径。
- REQ-21.2 一条任务的载荷无法读取、或执行器处理它时发生未捕获异常，不得停止后台执行器，也不得改变其他实例的任务。尚未开始执行的任务标为失败并释放该实例；已经离开预检或保存阶段的任务仍进入待处理，不自动重跑交换、清理或升级。
- REQ-21.3 定时备份仍按北京时间每日最多形成一份成功快照。当日任务在预检失败且尚未停服、尚未产生恢复点时，允许继续尝试，含首次最多 3 次。已成功、已取消、待处理、正在执行，或失败阶段已不是预检的任务，当天不再入队。
- REQ-21.4 修改备份时间或保留天数要求与恢复、清理、备份下载相同的近期管理员认证。普通会话只能查看策略。认证过期时保留管理员已填写的内容，验证身份后再次提交；取消不写入。
- REQ-21.5 管理员发起的操作错误保持显示，直到收起或下一次操作。实例采样、日志、主机和列表刷新失败单独提示，成功刷新后清除采样提示，不清除尚未收起的操作错误。
- REQ-21.6 判断实例是否有未结束任务时只查询一次数据库。实例地址在同一观测新鲜期内复用已采样结果，不因为列表刷新再检查一次容器。

以下不在本需求内：更换 Docker Engine API、把控制台每个页面拆成独立路由模块、取消排队任务或删除上传包的认证级别、生产部署和既有实例写操作。
