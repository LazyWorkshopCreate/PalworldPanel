# 内存展示与启动检查需求

日期：2026-10-07。状态：现行需求。范围：REQ-20，实例列表、新世界创建及实例启动。

- 实例列表展示“使用中 / 已分配 / 总内存”，使用中和总内存采用游戏运行环境的同一口径，已分配表示登记实例的配额及可识别外部配额，不代表实际占用。
- 已停止实例的配额不占用创建和启动预算；允许累计分配超过总内存，禁止仅因累计配额拒绝创建。
- 创建预检、正式提交和实际启动按实时可用内存检查，扣除系统预留和其他等待启动任务的预算。Windows 同时满足物理宿主和游戏运行环境的可用内存要求。
- 实时内存不足或无法读取时拒绝并明确提示原因；保持任务互斥、幂等及其他实例隔离。
- 已运行实例的备份、重启和规则维护恢复原运行状态，内存限额未增加时沿用既有运行分配，不按完整限额重复申请新增容量；显式启动和增加内存限额仍重新检查。

本需求替代运维初值中“停止实例也计入承诺总额、未知外部限额拒绝新建”的内存策略；外部容器的实际占用已经反映在实时可用内存中。
