1. 真实 `/settings` 返回 `CrossplayPlatforms`、`DenyTechnologyList` 为 JSON 数组。旧只读投影仅支持标量，导致这两个有效观测显示未知。修复仅对目录中声明为 list 的字段支持标量数组，以 `(Steam,Xbox,PS5,Mac)` / `()` 展示；嵌套对象、null 数组元素及非列表字段的数组仍拒绝投影，密码/网络等字段白名单保持不变。新增四项数组回归。
2. 真实容器日志含 ANSI 颜色转义。原流程仅删除 ESC 字符，遗留 `[1;36m`、`[0m` 等显示噪声。改为先完整删除 ANSI CSI 序列，再脱敏和清理控制字符；新增带颜色、夹带测试密码的日志回归。真实日志重跑无颜色码残片，凭据仍脱敏。

## 复现与收尾

脚本为 `tests/desktop_world_readonly.py`，必须显式传入 `--instance <测试实例Id>` 并检查 `desktopValidation`、固定测试卷路径和已存在的在线 DB 备份。`probe` 在挂载该测试卷的临时 Python 容器使用 `--network host` 直接读游戏；其他动作在 `.10` 白名单测试客户端执行。先将脚本及共用参数目录复制到测试卷的验收目录。

流程为：确认原测试面板停止、数据库备份、暂缓自动调度 → `configure`（仅适用于原游戏密码为空的专用夹具）→ `probe` → `backup` → `verify` → `stop` → `verify-offline` → `start` → `probe` / `verify` → `restore-config` → `restore-policy`。`browser` 只准备独立访客状态，私有状态文件使用系统临时目录且验收后撤销/清理。脚本不输出完整响应、密码或日志正文，不作为生产检查运行。

收尾已通过：通过 apply-config 恢复原空游戏密码并重新启动原世界；通过 API 恢复原备份时间与保留期，核实 Desired/Applied 一致且无活动任务。原访客 Cookie、临时游戏密码及空密码登录均 401，浏览器回到访问表单。私有浏览器状态和临时密码文件已删除；保留隔离卷内的在线 DB 备份、恢复点及下载校验记录用于回退/审阅。停止并移除本次创建的三个测试面板容器，旧测试面板、游戏实例和数据卷保留；用于访问的测试客户端和桥接恢复停止状态，原隔离游戏保持正常运行。

浏览器 CLI 首次下载使用默认工作目录，ZIP 曾进入仓库的忽略目录；发现含玩家存档路径后已移至系统临时目录，并确认仓库内不再留有本次世界的下载包。没有提交或输出玩家存档正文。后续浏览器验收在系统临时目录作为工作目录运行，截图使用仓库 output/playwright 的绝对目标路径，Cookie/ZIP/trace 不进入仓库。系统临时目录中的浏览器 ZIP 仅作用户本机审阅附件。
