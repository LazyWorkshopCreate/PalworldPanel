# 本机实例生命周期验收

日期：2026-10-07。范围：REQ-01–05、REQ-12；W03–W12 的本机实例管理验收。API 与网页验收通过；发布流水线结果在标签推送后另行核对。

## 环境与隔离

原 Windows 服务控制台在 18080，原游戏实例仅用于只读隔离核对。另启本机原生测试面板 18082，连接 Docker Desktop Linux 引擎，启用 DesktopValidation 并使用合成的新世界。运行配置、凭据、数据库、存档和备份均在仓库外的私有目录。测试实例使用 4 CPU / 4 GiB，与生产最低资源策略区分。

API 使用真实 Cookie 会话、CSRF、If-Match、单次确认预览和 Idempotency-Key；浏览器使用 Playwright CLI 操作实际页面，不以组件 mock 代替真实端到端证据。可重复的本机操作入口是 tests/native_lifecycle.py，需要显式提供本机 URL、私有凭据文件及合成实例 ID。

## 发现与修复

1. 新建预览未检查空间，正式创建留下失败实例。现于预览和提交检查同一空间安全余量；磁盘拒绝时不分配实例和任务。
2. 任务执行或待处理时，部分实例写操作仍可点击。现按 Queued、Running、NeedsAttention 统一锁定操作及参数、密码、备份策略和导入入口；后端继续校验互斥。
3. Windows 持有实例目录内锁文件时，目录隔离移动及清空失败。实例锁改存放 StateRoot/instance-locks，按稳定实例 ID 保持互斥；导出不能重新创建已清空目录。
4. 附加参数字典重新反序列化后，被引用比较误判为未应用草稿，导致升级被 DraftPending 拦截。现比较字段及字典内容，保留真正草稿未应用时的拒绝。
5. 备份用随机标识排序，列表时间无序且最新恢复点选择不可靠。现按实际创建时间倒序排序，并覆盖不同时区时间的回归检查。

6. 游戏 API 的空列表 `()` 被参数校验拒绝，受支持模板重新登记后无法识别世界及写接管。现接受合法空列表，并按实际游戏默认模板为 DenyTechnologyList 写入空赋值，避免 `()` 被游戏解释成 `NAME_None`；保留非法非空项目的拒绝。
7. 接管回退移除已停止的容器后，只读登记仍使用已失效的旧容器 ID。现通过 Docker 列表核实容器是否存在；确认不存在才按停止态接管，Docker 查询失败继续保持未知并拒绝执行。

## 验收边界

合成世界没有真实玩家身份；恢复、导入和升级均核对 PlayerVerificationPending 并演练回退，不伪造真实原玩家确认。相同批准镜像的升级验证安装保护、恢复点和配套回退，不证明不同游戏版本之间的存档兼容性。API 健康、端口映射和页面操作不等于真实游戏客户端入服或公网 UDP 可连接。
