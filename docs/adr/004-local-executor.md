# ADR-004：单服务器执行器和受支持写模板

日期：2026-10-06。状态：已采纳并在本机验证。补充 ADR-003 的实现机制，业务隔离/恢复决策继续保留。用户已授权依需求实现，生产操作仍另行授权。

## 决策

单面板进程整个生命周期持有 OS 独占 executor.lock，SQLite 条件领取/取消和每实例活动任务唯一约束配合实例文件锁。使用数据库有界轮询，不依赖内存通知或租约过期重新抢锁。Linux flock 和 Windows 文件共享限制分别验证。Web 监听成功后才开放 worker/scheduler；重启时未结束任务限制容器重启策略并转人工处理，不自动重放破坏阶段。

写管理仅支持已验证的单服务 JSON 形式 Compose（合法 YAML）、批准 digest、固定绑定/端口/限额、两个 raw env 文件。通用 YAML/anchors/额外覆盖/命令无法无损往返时只读。无自定义标签也能发现和登记；真实资源未知不能伪造默认限额。

新建使用无目录写入的预览 plan，确认后再次持分配锁核对端口、预算和克隆源修订；有变化拒绝并重新预览。预览不保留无限期端口租约，不把用户停留页面视为容量占用。备份/恢复/大复制共用单重 IO 门限。

## 取舍与验证

该方案符合单服务器维护范围，减少数据库租约/epoch 的双重机制。OS 锁只约束协作进程，不能阻止 root 手工写入；外部维护仍需停用面板写管理并使用同锁。多主机/多执行器不在支持范围。

实际 SQL/锁、文件阶段及进程中断、未知模板、新建预检证据见[验证记录](../verification/2026-10-06-desktop-implementation.md)。未模拟所有物理断电与 DB 提交边界，不据此保证生产恢复。当前 API 以[系统设计](../design/2026-10-06-system-design-r4.md)为准。
